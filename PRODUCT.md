# Product

## Platform

web

## Users

The portfolio serves prospective freelance clients and hiring managers or recruiters equally. Both audiences need to understand Rodney's experience and decide whether to get in touch.

## Product Purpose

Present Rodney Jan Mandap's professional experience, capabilities, and credentials, and give visitors a way to make contact.

## Positioning

The portfolio presents Rodney as a freelance software engineer building applications and software for internal and customer-facing products, with experience in Python, Django, automation, and APIs.

Automation means turning manual processes into end-to-end automated workflows using existing tools and systems, not building an automation platform from scratch.

## Capabilities and Constraints

- Preserve the contact form and its existing `/api/contact` submission, validation, spam protection, and feedback.
- Preserve access to the existing GitHub and LinkedIn profiles and certification links.
- The site is a responsive Next.js and TypeScript application. The separate private Level Up application is outside the portfolio's scope.
- Use the existing experience, certifications, and GitHub profile as evidence. Do not invent project case studies, client claims, testimonials, or performance metrics.
- Do not display an availability statement or the previous unexplained numerical skill scores. Individual project details are not confirmed by this brief.

## Brand Commitments

The portfolio uses the name Rodney Jan Mandap. The requested site should be minimal and attractive without looking like a typical AI-generated interface.

## Evidence on Hand

- Existing professional profile, skills, social links, and Microsoft certification references: `pages/index.tsx`.
- Existing portrait: `public/myPic.jpeg`.
- Existing logo assets: `public/logo-white-no-label.png` and related files in `public/`.
- No project case studies are currently displayed on the portfolio.

## Product Principles

- Help clients and hiring teams assess the same real experience quickly.
- Prefer specific, verifiable information to invented proof.
- Keep the path from evaluation to contact straightforward.
- Preserve working functionality while improving the portfolio.
